# 정약국 AI 상담봇 - 전체 아키텍처 설명

## 전체 흐름도

```
[약사님 PDF 파일] 
    ↓ 1단계: Google Document AI로 텍스트 추출
[구조화된 텍스트]
    ↓ 2단계: 문단별로 잘라서 의미 숫자(임베딩) 변환
[청크 + 임베딩]
    ↓ 3단계: Supabase pgvector에 저장
[스마트 도서관 완성]
    ↓ 사용자 질문 발생
[관련 문서 검색]
    ↓ 4단계: Claude Haiku가 자료 기반으로 답변 생성
[출처 + 안전 문구 포함 답변]
    ↓ 5단계: Next.js 챗봇 UI에 표시
```

## 각 기술의 역할

| 기술 | 비유 | 역할 |
|------|------|------|
| Google Document AI | 복사 전문 직원 | PDF 이미지를 텍스트로 변환 |
| Python 청킹 스크립트 | 가위 + 라벨 프린터 | 텍스트를 검색 가능한 크기로 잘라서 출처 표시 |
| OpenAI Embedding | 번역기 | 텍스트를 AI가 이해하는 숫자 형태로 변환 |
| Supabase pgvector | 스마트 도서관 | 숫자로 변환된 문서들을 의미 기반으로 검색 가능하게 보관 |
| Claude Haiku | 답변 작성 직원 | 찾아온 자료를 보고 자연스러운 한국어 답변 생성 |
| Next.js | 상담실 창구 | 사용자가 보는 채팅 화면 |

## 안전 설계 원칙

1. RAG 전용: 자료 없으면 답변 안 함
2. 출처 의무 표시: 문서명 + 페이지 번호
3. 위험 키워드 자동 감지 + 경고
4. 면책 문구 자동 추가
5. 진단/처방 자동 거부
